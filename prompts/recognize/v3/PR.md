# Улучшения промпта: v2 → v3

## Что изменилось

### Убран размытый лимит ответа

| Версия | Лимит ответа | Где задаётся |
|:------:|:-------------|:-------------|
| **v1** | `~500–800 токенов` | в тексте промпта |
| **v2** | — | контролируется через API |

**Почему это важно**

Лимит ответа должен регулироваться параметром `max_output_tokens` на стороне API, а не текстом промпта.

В v1 модель могла «пытаться» уложиться в 800 токенов, тратя дополнительные токены на подсчёт — вместо полезной работы.

## ✨ Плюсы v2 относительно v1

| № | Изменение | Эффект |
|:-:|:----------|:-------|
| 1 | Одна схема ответа вместо двух противоречивых | −30–40% токенов на выбор формата |
| 2 | Блок «Правила бюджета размышлений» | Прямое ограничение reasoning loop |
| 3 | Секционная структура промпта | Быстрее парсинг, меньше метаний |
| 4 | Однозначные правила для полуфабрикатов | Нет возвратов к пересмотру решения |
| 5 | Убран лимит ответа `~500–800 токенов` | Перенос контроля на API |
| 6 | Критерии отказа сжаты до одного прохода | Меньше времени на их проверку |
| 7 | Убрана двусмысленность «изделия кулинарии» | Меньше уточнений |

---

## ✅ Итог

**v3** устраняет все противоречия v2 и добавляет прямое противодействие reasoning loop.

После добавления `thinking_budget` в вызов API проблема с отклонением запросов должна уйти.
