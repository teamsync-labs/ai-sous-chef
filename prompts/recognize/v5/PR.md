# PR: Промпт нормализации продуктов v4 → v5

> **Тип изменений:** улучшение промпта  
> **Версия:** v4 → v5  
> **Область:** извлечение количества, запрет подмены и дополнения продуктов, термическая обработка ингредиентов

---

## Краткое описание

Обновление промпта AI-помощника по нормализации продуктов. Три ключевые цели:

1. **Стабильное извлечение** количества и единиц измерения в `quantity` / `unit`.
2. **Запрет подмены и дополнения** продуктов (сыр ≠ творог, горох ≠ чечевица, помидор ≠ помидор + яблоко).
3. **Обязательная термическая обработка** ингредиентов, которые нельзя есть сырыми (баклажан, картофель, свёкла, курица, грибы и др.).

---

## Проблемы в v4

### Проблема 1 — потеря количества

- Правила про количество разрознены, спрятаны в блоке «ПРАВИЛА ОБРАБОТКИ», подкреплены только одним примером.
- Модель возвращает `quantity: null`, `unit: null` при явно указанном количестве:
  - `«молоко 1л»` → `quantity: null` ❌
  - `«мука 2 кг»` → `quantity: null` ❌
- Нет whitelist единиц — модель может вернуть `"пачка"`, `"бутылка"` вместо `"шт"`.

### Проблема 2 — подмена и галлюцинация продуктов

- Сыр распознаётся как творог.
- Горох распознаётся как чечевица.
- Помидор превращается в «помидор + яблоко» — добавляется отсутствующий продукт.
- В v4 есть только общая фраза «Не добавляй продукты, которых нет во входных данных» — без примеров и без явного запрета семантической подмены.

### Проблема 3 — сырые ингредиенты в салатах

- Термообработка в v4 **отсутствует полностью**. Модель может советовать сырые баклажаны и картофель.
- Пример бага:
  > «Нарежьте баклажаны и картофель, добавьте в салат» ❌

### Проблема 4 — конфликт «отказ vs пустой список»

- В v4 критерий отказа №2 сформулирован как «Нет ни одного конкретного съедобного продукта» — без оговорки про готовые блюда.
- Нет раздела про возврат `{"products": []}`.

## Улучшения в v5

### 1️⃣ Добавлен отдельный блок «ИЗВЛЕЧЕНИЕ КОЛИЧЕСТВА»

Правила вынесены из «ПРАВИЛ ОБРАБОТКИ» в самостоятельный раздел с жёсткой формулировкой и явными правилами разбора.

**Было (v4):**
```text
- Если указано количество и единица — сохрани их.
- Если количество не указано — quantity: null, unit: null.
- Если указано количество без единицы — quantity: число, unit: null.
- Если указана единица без количества — quantity: null, unit: строка.
```

**Стало (v5):**
```text
Для каждого продукта проверь, указано ли количество во входных данных.
Если указано — обязательно перенеси его в поля quantity и unit.
Никогда не оставляй quantity: null, если во входе есть число или единица.

Правила разбора:
- «2 кг», «1.5 л», «500 г» → quantity: число, unit: строка.
- «полкило» → quantity: 0.5, unit: "кг".
- «полтора литра» → quantity: 1.5, unit: "л".
- «пачка», «упаковка», «батон», «бутылка» → unit: "шт".
- «немного», «чуть-чуть», «по вкусу» → quantity: null, unit: null.
- Десятичные — только точка.
- Whitelist единиц: "шт", "кг", "г", "л", "мл".
```

**Зачем:** правила, спрятанные в середине блока, не привлекали внимания модели.

---

### 2️⃣ Усилен блок «ФОРМАТ ОТВЕТА»

**Было (v4):** только требование `{` первым символом и схема.

**Стало (v5):** добавлен контрольный абзац:

> Перед выводом проверь: если во входе у продукта было число/единица — в JSON это число/единица должны присутствовать. Пустой `quantity` при наличии данных во входе считается ошибкой.

---

### 3️⃣ Добавлен блок «ЗАПРЕТ НА ДОПОЛНЕНИЕ И ПОДМЕНУ»

**Было (v4):**
```text
- Не добавляй продукты, которых нет во входных данных.
- Не придумывай категории и описания.
```

**Стало (v5):** отдельный блок с 5 правилами и явными примерами подмены:

```text
ЗАПРЕТ НА ДОПОЛНЕНИЕ И ПОДМЕНУ

1. Называй продукт только тем словом, которое соответствует изображению.
2. НЕ заменяй продукт на семантически близкий:
   - сыр ≠ творог
   - горох ≠ чечевица
   - помидор ≠ яблоко
3. НЕ добавляй продукты, которых нет на фото/во входе.
4. Если не уверен в точном названии — используй обобщённое слово
   ("сыр", а не "творог") ИЛИ понизь confidence, но НЕ подменяй.
5. Если распознал N объектов — в JSON должно быть ровно N продуктов.
```

---

### 4️⃣ Добавлен блок «ТЕРМИЧЕСКАЯ ОБРАБОТКА ИНГРЕДИЕНТОВ»

**Было (v4):** отсутствует.

**Стало (v5):** отдельный раздел со списком обязательной обработки и требованиями к описанию:

```text
Обязательно обрабатывать: картофель, баклажан, кабачок, тыква, свёкла,
грибы (кроме маринованных), курица, мясо, рыба, морепродукты, яйцо,
сухие бобовые, крупы, макароны.

Для каждого такого ингредиента укажи:
1. Способ: отварить / запечь / обжарить / припустить / бланшировать.
2. Время и ориентир готовности: "20–25 мин до мягкости".
3. Температуру: "при 200 °C".
4. Обязательное охлаждение: "остудите до комнатной температуры".
5. Только после этого: "нарежьте и добавьте в салат".
```

Также в «ПРАВИЛА ОБРАБОТКИ» добавлена общая формулировка:

> Если ингредиент нельзя безопасно и вкусно есть сырым — он должен пройти термическую обработку в рецепте.

### 6️⃣ Уточнён критерий отказа №2

**Было (v4):**
```text
2. Нет ни одного конкретного съедобного продукта.
```

**Стало (v5):**
```text
2. Нет ни одного конкретного съедобного продукта И вход не является
   описанием готового блюда (см. раздел про готовые блюда).
```

**Зачем:** в v4 готовое блюдо могло ложно попасть под отказ, хотя по разделу «КАК ОБРАБАТЫВАТЬ ГОТОВЫЕ БЛЮДА» должно возвращать базовые продукты.

---

### 7️⃣ Добавлен раздел «ЧТО ДЕЛАТЬ, ЕСЛИ ПРОДУКТЫ НЕ РАСПОЗНАНЫ»

**Было (v4):** отсутствует — модель либо возвращала JSON, либо отказ, промежуточного состояния нет.

**Стало (v5):**
```json
{"products": [], "confidence": 0.0}
```

> Если вход не подпадает под критерии отказа, но конкретные продукты определить не удалось — вернуть пустой список.

---

### 8️⃣ Расширен алгоритм: 4 → 7 шагов

```diff
  1. Проверь входные данные на критерии отказа — один раз.
  2. Если сработал отказ — верни фразу ошибки.
  3. Иначе — собери список продуктов по правилам выше.
+ 4. Для каждого продукта извлеки количество и единицу по блоку «ИЗВЛЕЧЕНИЕ КОЛИЧЕСТВА».
+ 5. Удали дубликаты.
+ 6. Проведи самопроверку (см. ниже).
  7. Сразу верни JSON без markdown-обёрток.
```

---

### 9️⃣ Добавлен блок «САМОПРОВЕРКА ПЕРЕД ОТВЕТОМ»

**Было (v4):** отсутствует.

**Стало (v5):**
```text
1. Все ли числа из входа попали в quantity?
2. Все ли единицы измерения нормализованы в "шт/кг/г/л/мл"?
3. Нет ли дубликатов после нормализации?
4. Первый символ — «{»?
```

## 💡 Рекомендации на стороне вызова (вне промпта)

| Параметр | Значение | Зачем |
|---|---|---|
| `temperature` | `0–0.2` | Снижает вариативность и фантазии модели |
| `response_format` | `{ type: "json_object" }` или `json_schema` с `enum` | Валидный JSON / запрет подмены на уровне декодирования |
| Prefill | `{"products": [` | Устраняет markdown-обёртки |
| Post-check | regex-фильтр запрещённых формулировок | Ловит сырые ингредиенты в салате |
| Reverse-check | второй вызов «есть ли продукт X на фото?» | Убирает галлюцинации |

## Регресс-тестирование

### Количество и отказы

| Вход | Ожидаемый результат | Что проверяет |
|---|---|---|
| мука 2 кг, сахар 500г, яйца 10 штук | Все три с `quantity`/`unit` | Основной кейс |
| полкило картошки, бутылка воды | `0.5 кг` и `null шт` | Пограничные формы |
| молоко полтора литра | `1.5 л` | Разговорное количество |
| соль по вкусу | `null` / `null` | Отсутствие количества |
| авыавыа sdfghjk | Ошибка | Критерий отказа |
| на фото салат с помидорами | помидоры, без отказа | Уточнённый критерий №2 |

### Подмена и дополнение

| Вход | Ожидание | Что ловит |
|---|---|---|
| фото ломтика сыра | `["сыр"]` | Подмена сыр → творог |
| фото гороха | `["горох"]` | Подмена горох → чечевица |
| фото помидора | `["помидор"]` ровно 1 | Галлюцинация «+яблоко» |
| фото пустой тарелки | `[]` или отказ | Ложное добавление |

### Термообработка

| Запрос | Что должно быть | Что НЕ должно быть |
|---|---|---|
| Салат с баклажаном и картофелем | «запеките баклажан», «отварите картофель», «остудите» | «сырые баклажаны», «нарежьте и добавьте» без обработки |
| Салат со свёклой и курицей | «отварите свёклу 1–1.5 ч», «отварите/запеките курицу», «остудите» | «сырая свёкла», «сырая курица» |
| Салат с грибами | «обжарьте грибы до испарения влаги» | «сырые шампиньоны» |
| Салат с огурцом и помидором | «нарежьте свежие огурцы и помидоры» | лишние этапы варки |
| Салат с консервированным горошком | «добавьте горошек из банки» | «отварите горошек» |
