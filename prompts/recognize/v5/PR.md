# Промпт нормализации продуктов v4 → v5

> **Тип изменений:** улучшение промпта  
> **Версия:** v4 → v5  
> **Область:** извлечение количества и единиц измерения ингредиентов

---

## 📌 Краткое описание

Обновление промпта AI-помощника по нормализации продуктов. Цель — заставить модель стабильно извлекать количество и единицы измерения из входных данных и переносить их в поля `quantity` / `unit` итогового JSON.

---

## 🐛 Проблема в v4

- Правила про количество разрознены и подкреплены только одним примером.
- Модель часто возвращает `quantity: null`, `unit: null` при явно указанном количестве:
  - `«молоко 1л»` → `quantity: null` ❌
  - `«мука 2 кг»` → `quantity: null` ❌
- Конфликт между критериями отказа и правилом обработки готовых блюд.

---

## ✨ Улучшения в v5

### 1️⃣ Выделен отдельный блок «Извлечение количества»

Правила вынесены из «Правил обработки» в самостоятельный раздел с жёсткой формулировкой:

- Для **КАЖДОГО** продукта проверь, указано ли количество.
- Если указано — **ОБЯЗАТЕЛЬНО** перенеси его в `quantity` и `unit`.
- **Никогда** не оставляй `quantity: null`, если во входе есть число или единица.

> **Зачем:** правила, спрятанные в середине блока, не привлекали внимания модели.

### 2️⃣ Закрыты пограничные случаи парсинга

Добавлены явные правила для случаев, которые раньше не были описаны:

| Вход | quantity | unit |
|---|---|---|
| `2 кг`, `1.5 л`, `500 г` | число | строка |
| `полкило` | `0.5` | `"кг"` |
| `полтора литра` | `1.5` | `"л"` |
| `пачка`, `бутылка`, `батон` | как указано | `"шт"` |
| `немного`, `по вкусу` | `null` | `null` |

- Единицы приводятся строго к whitelist: `"шт"` · `"кг"` · `"г"` · `"л"` · `"мл"`.
- Десятичные — только с точкой (`1.5`, а не `1,5`).

### 3️⃣ Усилен блок «Формат ответа»

Добавлен контрольный абзац перед схемой:

> Перед выводом проверь: если во входе было число/единица — в JSON они **ДОЛЖНЫ** присутствовать.  
> Пустой `quantity` при наличии данных во входе считается ошибкой.

### 4️⃣ Расширен набор примеров: 3 → 6

| # | Пример | Покрывает |
|---|---|---|
| 1 | яйца, молоко 1л, сыр | Базовый кейс |
| 2 | салат с помидорами, хлеб | Готовое блюдо |
| 3 | мука 2кг, сахар 500г, яйца 10шт, соль по вкусу, молоко полтора литра | Разные форматы количества |
| 4 | пачка масла, 3 банана, литр кефира | Единица без числа / число без единицы |
| 5 | полкило картошки, бутылка воды, 200 мл сливок | Разговорные формы и нормализация |
| 6 | авыавыа sdfghjk | Отказ |

**Итог:** примеров с количеством стало 4 вместо 1.

### 5️⃣ Разрешён конфликт «отказ vs пустой список»

Критерий отказа №2 уточнён:

> Нет ни одного съедобного продукта **И** вход не является описанием готового блюда.

Добавлен новый раздел:

```json
{"products": [], "confidence": 0.0}
```

> Если вход валиден, но продукты не распознаны — возвращается пустой массив, а не ошибка.

### 6️⃣ Алгоритм расширен с 4 до 9 шагов

```diff
  1. Проверь входные данные на критерии отказа.
  2. Если сработал отказ — верни фразу ошибки.
  3. Иначе — собери список продуктов.
+ 4. Для каждого продукта извлеки количество и единицу.
+ 5. Проверь по справочнику: нет ли подмены или лишних продуктов.
+ 6. Для рецептов салатов — определи категорию термообработки каждого ингредиента.
+ 7. Добавь этапы обработки и охлаждения для «обязательных» ингредиентов.
+ 8. Удали дубликаты и проведи самопроверку.
  9. Сразу верни JSON без markdown-обёрток.
```

### 7️⃣ Добавлен блок «Самопроверка перед ответом»

```text
1. Все ли числа из входа попали в quantity?
2. Все ли единицы нормализованы в "шт/кг/г/л/мл"?
3. Нет ли подмены продукта (сыр→творог, горох→чечевица)?
4. Нет ли продуктов, которых не было на входе/фото?
5. Для салатов: все ли «обязательные» ингредиенты прошли термообработку?
6. Указан ли способ, время и признак готовности для каждого?
7. Есть ли шаг «остудите» перед добавлением в салат?
8. Нет ли дубликатов после нормализации?
9. Первый символ — «{»?
```

# Промпт нормализации и генерации рецептов v4 → v5

> **Тип изменений:** улучшение промпта  
> **Версия:** v4 → v5  
> **Область:** извлечение количества, запрет подмены продуктов, термическая обработка ингредиентов в салатах

---

## Краткое описание

Комплексное обновление промпта AI-помощника по нормализации продуктов и генерации рецептов. Три ключевые цели:

1. **Стабильное извлечение** количества и единиц измерения в поля `quantity` / `unit`.
2. **Запрет подмены и дополнения** продуктов (сыр ≠ творог, горох ≠ чечевица, помидор ≠ помидор + яблоко).
3. **Обязательная термическая обработка** ингредиентов, которые нельзя есть сырыми (баклажан, картофель, свёкла, курица, грибы и др.).

---

## Проблемы в v4

### Проблема 1 — потеря количества

- Правила про количество разрознены и подкреплены только одним примером.
- Модель часто возвращает `quantity: null`, `unit: null` при явно указанном количестве:
  - `«молоко 1л»` → `quantity: null` ❌
  - `«мука 2 кг»` → `quantity: null` ❌
- Конфликт между критериями отказа и правилом обработки готовых блюд.

### Проблема 2 — подмена и галлюцинация продуктов

- Сыр распознаётся как творог.
- Горох распознаётся как чечевица.
- Помидор превращается в «помидор + яблоко» — модель добавляет отсутствующий продукт.
- Корень: модель работает как генератор вероятного, а не как извлекатель точного.

### Проблема 3 — сырые ингредиенты в салатах

- В рецептах салатов баклажаны, картофель, свёкла, курица, грибы добавляются **сырыми**.
- Отсутствует этап термической обработки и охлаждения.
- Пример бага:
  > «Нарежьте баклажаны и картофель, добавьте в салат» ❌

#### Добавлен блок «ЗАПРЕТ НА ДОПОЛНЕНИЕ И ПОДМЕНУ»

```text
🚫 ЗАПРЕТ НА ДОПОЛНЕНИЕ И ПОДМЕНУ

1. Называй продукт ТОЛЬКО тем словом, которое соответствует изображению.
2. НЕ заменяй продукт на семантически близкий:
   - сыр ≠ творог
   - горох ≠ чечевица
   - помидор ≠ яблоко
3. НЕ добавляй продукты, которых нет на фото/во входе.
   Каждый продукт в JSON должен быть обоснован видимым объектом или словом из входа.
4. Если не уверен в точном названии — используй обобщённое слово
   ("сыр", а не "творог"; "бобовые", а не "чечевица")
   ИЛИ понизь confidence, но НЕ подменяй.
5. Если распознал N объектов — в JSON должно быть ровно N продуктов.
   Проверь: нет ли лишних записей.
```

### Термическая обработка ингредиентов в салатах

#### Добавлен справочник категорий обработки

| Категория | Ингредиенты | Требуется обработка |
|---|---|---|
| 🔥 **Обязательно термически** | картофель, баклажан, кабачок, тыква, свёкла, морковь (в салате), грибы (кроме маринованных), курица, мясо, рыба, яйцо, бобовые (сухие), крупы, макароны | да |
| ♨️ **Опционально** | морковь (корейская — сырая), лук (можно мариновать), перец (можно запечь), капуста (можно обжарить) | зависит от рецепта |
| 🥗 **Сырые** | огурцы, помидоры, листья салата, руккола, шпинат, редис, болгарский перец, зелень, авокадо, яблоко | нет |
| 🧀 **Готовые к употреблению** | сыр, консервы, маринованные овощи, колбаса, оливки, орехи | нет |

```text
ЭТАП ТЕРМИЧЕСКОЙ ОБРАБОТКИ (обязательный)

Для каждого ингредиента салата:
1. Определи категорию по справочнику выше.
2. Если категория «Обязательно термически»:
   - В описании приготовления ДОБАВЬ явный шаг обработки:
     отварить / запечь / обжарить / припустить / бланшировать
   - Укажи время и способ: "отварите картофель 20–25 мин до мягкости"
   - Обязательно укажи: "остудите до комнатной температуры"
   - Только после этого — "нарежьте и добавьте в салат"
3. Если ингредиент можно использовать сырым — явно напиши "сырой" или "свежий".
4. НЕЛЬЗЯ добавлять в салат сырыми: картофель, баклажан, кабачок, тыкву,
   свёклу, грибы, мясо, курицу, рыбу, яйцо, сухие бобовые, крупы, макароны.
```

| `temperature` | `0–0.2` (нормализация), `0.3–0.5` (рецепты) | Снижает вариативность / сохраняет вариативность рецептов |
| `response_format` | `{ type: "json_object" }` или `json_schema` с `enum` | Гарантирует валидный JSON / запрещает подмену на уровне декодирования |
| Prefill | `{"products": [` | Устраняет markdown-обёртки |
| Post-check | regex-фильтр запрещённых формулировок | Ловит сырые ингредиенты в салате |
| Reverse-check | второй вызов «есть ли продукт X на фото?» | Убирает галлюцинации |

## Регресс-тестирование

### Количество и отказы

| Вход | Ожидаемый результат | Что проверяет |
|---|---|---|
| мука 2 кг, сахар 500г, яйца 10 штук | Все три с `quantity`/`unit` | Основной кейс |
| полкило картошки, бутылка воды | `0.5 кг` и `null шт` | Пограничные формы |
| молоко полтора литра | `1.5 л` | Разговорное количество |
| соль по вкусу | `null` / `null` | Отсутствие количества |
| авыавыа sdfghjk | Ошибка | Критерий отказа |
| на фото салат с помидорами | помидоры, без отказа | Уточнённый критерий №2 |

### Подмена и дополнение

| Вход | Ожидание | Что ловит |
|---|---|---|
| фото ломтика сыра | `["сыр"]` | Подмена сыр → творог |
| фото гороха | `["горох"]` | Подмена горох → чечевица |
| фото помидора | `["помидор"]` ровно 1 | Галлюцинация «+яблоко» |
| фото пустой тарелки | `[]` или отказ | Ложное добавление |

### Термообработка

| Запрос | Что должно быть | Что НЕ должно быть |
|---|---|---|
| Салат с баклажаном и картофелем | «запеките баклажан», «отварите картофель», «остудите» | «сырые баклажаны», «нарежьте и добавьте» без обработки |
| Салат со свёклой и курицей | «отварите свёклу 1–1.5 ч», «отварите/запеките курицу», «остудите» | «сырая свёкла», «сырая курица» |

| Салат с огурцом и помидором | «нарежьте свежие огурцы и помидоры» | лишние этапы варки |
| Салат с консервированным горошком | «добавьте горошек из банки» | «отварите горошек» |
