# MVP AI Sous-Chef

## Что мы делаем

AI Sous-Chef — персональный помощник на кухне, который помогает решить главный вопрос: «Что приготовить?»

Цель — создать полезный AI-продукт и одновременно получить опыт командной разработки.

ЦА: Первая целевая аудитория — люди, которые регулярно готовят дома.

Архитектурные решения: единый backend, AI только через backend

## Ключевые принципы

1. Без авторизации — пользователь начинает работу сразу, без входа и регистрации. Это снижает порог входа и позволяет быстрее проверить гипотезу.
2. Два способа ввода запроса — пользователь может отправить фото продуктов или ввести их текстом. Оба сценария ведут к одному результату — подбору рецептов.
3. Отсутствие чата — мы не реализуем диалоговый интерфейс. Каждый запрос обрабатывается как отдельное действие, история не хранится (упрощает разработку и защищает данные).
4. Минимальная работа с персональными данными — мы не запрашиваем и не храним личную информацию пользователей. Всё, что попадает в бот, — только продукты и запросы.

Данные в Telegram- согласовать как это сделать корректно с точки политики конфиденциальности Telegram.

## В MVP сознательно не входят

- список покупок;
- планирование меню;
- учёт калорий;
- персональные диеты;
- социальные функции;
- интеграция с умной техникой;
- сложная система хранения продуктов.

Эти идеи могут появиться после завершения MVP.

## Работа Telegram бота

### Сценарий А: пользователь делает фото

| Шаг | Действие пользователя | Реакция системы |
|-----|----------------------|-----------------|
| 1 | Открывает бота, нажимает кнопку /start | Бот отправляет ознакомительное сообщение |
| 2 | Пользователь отправляет фото | Бот распознаёт продукты (до 5 секунд). Видит сообщение: «Продукты распознаны: [список]» + кнопки ✅ Верно / ❌ Не верно |
| 3 | Видит сообщение: «Продукты распознаны: [список]» + кнопки ✅ Верно(Да) / ❌ Неверно (Нет) | Бот ожидает выбора. Текстовый ввод не блокируется. Всегда ждем новый запрос. |
| 4 | Нажимает ✅ Верно(Да) | Бот ищет рецепты и выдаёт список |
| 5 | Нажимает ❌ Неверно(Нет) | Если после распознавания фото ответ нет- ответ “Попробуйте отправить фото еще раз” |
| 6 | Получает рецепты | Если после распознавания фото есть текстовый запрос - считаем его новым запросом. |

### Сценарий Б: Пользователь вводит ТЕКСТ

| Шаг | Действие пользователя | Реакция системы |
|-----|----------------------|-----------------|
| 1 | Открывает бот, нажимает кнопку /start | Бот отправляет ознакомительное сообщение |
| 2 | Пишет в чат. Вводит продукты (например: «курица, рис, лук») | Бот распознаёт продукты (до 5 секунд). Видит сообщение: «Продукты распознаны: [список]» + кнопки ✅ Верно / ❌ Не верно |
| 3 | Нажимает ✅ Верно(Да) | Бот сразу ищет рецепты по тексту (распознавание НЕ запускается) |
| 4 | Нажимает ❌ Неверно(Нет) | Видит сообщение “Попробуйте отправить текст еще раз” |
| 5 | Пользователь получил рецепт | Текстовый ввод не блокируется. Всегда ждем новый запрос. Один запрос- один ответ. Следующий текстовый запрос - новый ответ. |

## Работа мобильного приложения (mobile app)

### Сценарии работы (Mobile App)

Пользователь переходит в приложение видит главный экран с кнопками фото и текст. Возле них написана краткая инструкция как пользоваться режимом.

### Сценарий А: Пользователь отправляет ФОТО

| Шаг | Экран / Действие пользователя | Что происходит в системе |
|-----|------------------------------|--------------------------|
| 1 | На главном экране нажимает «📸 Фото» | Открывается камера (через Android SDK) |
| 2 | Делает фото продуктов | Экран после фото - чат без поля ввода текста. Начинается распознавание фото. |
| 3 | (После распознавания) Видит экран «Продукты распознаны» со списком продуктов и двумя кнопками: ✅ Верно / ❌ Не верно | Система показывает результат распознавания. Поле ввода текста на этом экране скрыто (чтобы пользователь не путался) |
| 4 | Нажимает ✅ Верно | Система ищет рецепты по распознанному списку и показывает их |
| 5 | Нажимает ❌ Не верно | Пользователь видит сообщение “Попробуйте отправить фото еще раз” |
| 6 | (После получения рецептов) Нажимает кнопку «🏠 На главную» | Можно начать новый запрос, пользователь находится на главном экране |

### Сценарий Б: Пользователь вводит ТЕКСТ

| Шаг | Экран / Действие пользователя | Что происходит в системе |
|-----|------------------------------|--------------------------|
| 1 | На главном экране нажимает «✏️ Текст» | Открывается экран с полем для ввода и кнопкой «Найти рецепты» |
| 2 | Вводит продукты, например: «курица, рис, лук» | Система сразу ищет рецепты по тексту (без распознавания) |
| 3 | Получает список рецептов | Приложение показывает результат. Появляется кнопка «🏠 На главную» |
| 4 | Нажимает «На главную» | Возврат на главный экран, сброс контекста |

## Дорожная карта

План может корректироваться по мере развития проекта.

### Неделя 1

- знакомство команды;
- согласование Vision и MVP;
- подготовка пользовательских сценариев;
- настройка репозитория и рабочего окружения.

### Неделя 2

- каркас backend;
- каркас мобильного приложения;
- каркас Telegram-бота;
- первые AI-эксперименты.

### Неделя 3

- загрузка фотографии;
- распознавание продуктов;
- интеграция с LLM;
- первые пользовательские сценарии в мобильном приложении и Telegram.

### Неделя 4

- генерация рецептов;
- отображение рецептов;
- интеграционное тестирование.

### Неделя 5

- улучшение UX;
- обработка ошибок;
- стабилизация основных пользовательских сценариев.

### Неделя 6

- исправление найденных проблем;
- подготовка публичного релиза;
- актуализация документации;
- демонстрация MVP.

При необходимости проект может занять ещё 1–2 недели на тестирование и завершение оставшихся задач.
